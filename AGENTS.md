# Family Agents V2

Family Agents is a private LAN control panel for family-owned Matrix AI accounts. People use their existing Matrix clients to chat. The web UI has no login, administrator, roles, or chat interface. Write all source, comments, documentation, UI labels, and commits in English. Never commit private data or credentials.

## Architecture and boundaries

Exactly one Node.js/TypeScript process serves Hono and the React UI, owns SQLite metadata, supervises one Rust child, and selects one global Agent Runtime. `AgentRuntime` in `server/runtime.ts` exposes only application behavior. `PiRuntime` wraps the official embedded Pi SDK; `CodexRuntime` supervises one shared `codex app-server` over stdio with an independent persistent thread for each Agent. `RuntimeManager` holds these two adapters; do not add a plugin framework. The Rust child uses the official matrix-rust-sdk for all Agent accounts, authentication, sync, E2EE, profiles, and media. IPC is versioned JSONL on stdin/stdout; logs belong on stderr. Keep runtime SDK/protocol types inside adapters and all runtime logic out of Rust.

Each Person has a unique full Matrix ID. Each Agent belongs to one Person and has a dedicated Matrix account. Accept only decrypted messages from that owner, in an encrypted invite-only one-to-one room recorded in Matrix direct-message account data. Discover already-joined owner DMs as well as new direct invitations: after checking the authoritative pair, invite-only rules, encryption, and direct membership evidence, repair a missing Agent-side `m.direct` entry. Never require a newly created test room. Check authoritative active membership, including invitations, before execution and every send. Ignore self/outsider/group messages. Never trust frontend state for routing.

Keep the existing main-timeline session for each Agent and runtime. Open separate persistent sessions lazily for Matrix threads, keyed by the verified Agent, homeserver, owner, room, and root. Retain native history on stop and restart, with bounded live sessions. Root text can seed a new session as untrusted background. Carry the root and owner event through the durable inbox and outbox so text, artifacts, notices, and scheduled deliveries stay in the source thread. Match active cancellation to the same room and thread or main timeline. Treat edits as changes to existing messages, never new requests.

Global settings contain the homeserver, default provider/model, and thinking level. Agents contain only Matrix ID/password, display name, avatar, and instructions. Pi owns native provider/auth configuration, its catalog, capability-derived thinking levels, persistent sessions, and automatic compaction. Use built-in providers for official services; do not create duplicate application-branded provider aliases. Provider authentication has one Configure Provider action for native API-key setup, plus Sign In only where account authorization is supported. Keep the complete native JSON editor inside a collapsed Advanced Provider Configuration section. Routine connections must not require raw JSON editing. Keep all native schema properties through JSON edits and redact secrets in every response/error, while leaving ordinary token-limit metadata readable. The Default Model selector lists only SDK-available models from configured providers. Preserve an unavailable saved selection as an explanatory message rather than selecting a replacement, and prompt for provider setup when the list is empty. Use Pi's capability helpers, including custom thinking maps and Max support. Apply global model/thinking changes between turns.

Pi exposes no general shell, filesystem, network, MCP, or automatically discovered extension tools. Both runtimes share exactly eight fixed application tools from `server/app-tools.ts`: `reminder_create`, `reminder_list`, `reminder_cancel`, `briefing_subscribe`, `briefing_list`, `briefing_cancel`, `export_file`, and `python_analyze`. Runtime adapters expose the same definitions and trusted invocation closures; keep provider-specific tool plumbing inside the adapters. Bind every invocation to the active Agent, homeserver, owner, room, source event, and cancellation signal; never accept routing identity from model arguments. Check scope and authoritative room membership before and after asynchronous work. Scheduled or retrieved content cannot authorize schedule creation or cancellation.

Codex's sole MCP exception is the application-owned loopback bridge in `server/runtime-tool-server.ts`, hosted inside the existing Node process. It exposes only the fixed tools, listens on loopback, rejects browser origins, and authenticates each active-turn registration with a fresh scope token. Revoke access on completion or cancellation, reject stale invocations, and keep the token out of logs and user-visible output. Tool call IDs are deduplicated and conflicting arguments rejected. Do not enable arbitrary MCP servers, remote tool registration, automatic discovery, filesystem resources, or unrestricted execution. This bridge is not a new infrastructure service.

Both runtimes receive locally extracted text from supported encrypted Matrix documents; fixed parsers receive only attachment bytes on stdin, never model commands or file paths. Validate format and 8 MiB size before durable admission, bound extracted input to 48,000 characters including the owner caption, and revalidate room membership after parsing. Codex uses an isolated private home, disabled execution/extension discovery, and native live web search where the model/account permits it. Use the named `family_agent` permission profile with native filesystem access denied and command network disabled on process defaults, thread start/resume/fork, and every turn; do not override it with legacy sandbox fields. Reject unsupported approval requests; never automatically grant execution or file permissions. The fixed `send_image` tool can only return an image attached to the current message. Native image generation may use text or images already in the same conversation; local image paths must be denied before upload. Enable it only outside SIWC and let native model/account gates apply. Accept generated bytes or the exact private native thread/item artifact, validate image type/size and links, correlate the active turn, deduplicate completion events, and cap output to four images/8 MiB total. Instructions append to Pi's essential prompt or use Codex's persistent developer instructions, isolated by Agent.

Export only CSV tables and PDFs containing supplied text/tables. Local Python accepts structured table data and fixed `describe`, `group`, or `correlation` operations, with optional bar, line, scatter, or histogram charts. Never accept model-generated Python, shell commands, imports, filesystem paths, or network operations. Run the fixed worker with isolation, a private temporary directory, bounded resources, cancellation, and cleanup; do not turn it into a general execution environment. Preserve CSV formula escaping. Enforce 2 MiB structured input, 30 columns, 5,000 rows (1,000 for PDF tables), 48,000 PDF text characters, and 4,096 characters per cell. Grouped analysis allows 100 groups; each call returns at most one PNG, bar charts show the first 100 records, and histogram bins range from 5 to 100. Each generated file/chart is at most 8 MiB; reply delivery permits four files and 16 MiB combined files/images. Files and charts use the existing encrypted durable outbox; do not invent download URLs or expose local paths.

Responses Lite models invoke native tools through the isolated Code Mode host. Keep `features.code_mode_host=true` and the matching `codex-code-mode-host` companion installed, while shell/browser/computer-use tools remain disabled and `features.code_mode=false`. The SIWC provider must declare `supports_standalone_web_search=true`; `web_search=live` alone does not expose that provider's search tool. SIWC search uses `/v1/alpha/search`, which has separate authorization requirements from `/v1/responses`; managed native ChatGPT uses its own built-in Codex backend and authentication. A successful SIWC login or model turn does not prove search entitlement. Report a search authorization failure accurately; never enable unrestricted execution or change authentication routes to hide it. The gateway renders Markdown for model replies. Use descriptive Markdown source links with direct HTTPS URLs because Matrix cannot resolve opaque native citation markers.

Runtime selection defaults to Pi for existing installations. Settings retain independent defaults for Pi and Codex; provider configuration stays Pi-native. Codex retains three explicitly selected connections: current open-source Sign in with ChatGPT, Codex-managed native ChatGPT login, and native API-key login. Keep their credentials independent; signing out clears only the selected connection. Existing SIWC remains selected on upgrade. `ChatGptAuth` owns protected registrations, a stable host ID, PKCE/state/nonce, verified identity tokens, manual callback-URL input, and serialized rotating-token refresh. It is separate from Pi credentials and the desktop Codex account. Never automatically fall back between connections after an authorization or search failure. Native OAuth and rotating-token refresh stay owned by Codex; snapshot its latest opaque credential file only after the child stops, and restore the selected cache before starting it. Pending native login must prevent new executions from crossing its authentication change. Codex model discovery and reasoning metadata still use native `model/list`. Pass SIWC access tokens only in the child environment to the documented Responses provider at `https://api.openai.com/v1`; never in process arguments, logs, or HTTP responses. Refreshing the token may restart the shared App Server only after existing execution leases drain; new turns wait and saved threads resume without replay. Internal cancellation must not wait for its own execution lease. Keep the public SIWC provider definition registered in native/API-key mode so stored SIWC history can resolve its original provider; supply its token only when SIWC is selected. A provider mismatch after an explicit connection switch requires native `thread/fork` with the saved history; retain the source, persist the new mapping, and never replay an old turn. Do not treat missing history or arbitrary resume errors as a provider mismatch. Authentication completion restores desired Agents and starts only missing Matrix clients. Gateway Running status proves transport connectivity; it must not clear a runtime/session/delivery error. Clear those errors only after explicit recovery or a successful fresh operation.

Validate target readiness before switching. Pause new turns while durably admitting Matrix events, drain active Agent operations (cancel after a bounded wait), prepare target sessions, deactivate the old runtime, then persist selection. Restore the previous runtime on failure. Never restart Matrix devices just to switch runtimes, convert session formats, replay an uncertain execution, or delete conversation data during switching. Codex process exits fail active turns and reconnect only for fresh operations. Use separate locks for settings writes and Agent queues so draining Agent operations cannot wait on its own settings write.

## Storage and consistency

`DATA_DIR` defaults to `data/`, with mode 0700 and files 0600:

- `application.sqlite`: People, Agent metadata, optimistic versions, global settings, durable inbox/outbox, and `ScheduleStore` schedules/execution records. Matrix passwords are in a separate encrypted credentials table; `credentials.key` must be backed up with it.
- `pi/models.json`, `pi/auth.json`: Pi-native configuration and authentication, accessible only to the service account.
- `agents/<id>/sessions/`: Pi-native persistent conversation files; restore automatically. No session state is duplicated in SQLite.
- `codex/home/`: private Codex-native credentials and conversation storage; `codex/agents/<id>/` contains isolated internal working directories and atomic thread mappings. Keep these independent from Pi sessions and the desktop user's Codex account.
- `codex/auth-connections/`: private explicit-method selection and separate opaque native ChatGPT/API-key credential snapshots. Preserve rotated native credentials during switching and rollback.
- `codex/siwc/`: private Sign in with ChatGPT host identity, separately retained account/client registrations, and renewable credentials. Write credentials atomically with 0600 permissions. Verify issuer/signature/audience/expiry/nonce and direct-use scopes before activating an account; preserve the previous connection if authorization fails. Sign-out clears tokens, retains account/client mappings, and attempts remote renewable-session revocation.
- `matrix/<id>/`: SDK SQLite state/crypto stores, original device session, sync cursor, durable pending-event spool, and private native `identity-secrets.json`. Match all recovered signing public keys against the server before importing, sign the current device with the existing identity, and preserve signing secrets separately across bounded crypto-DB recovery. Never replace an unknown account identity. Acknowledge spool events only after SQLite admission commits. Restore normal devices; classified corruption recovery is bounded and archives the previous state.

Serialize messages and lifecycle changes per Agent; different Agents run concurrently. Check record versions under the same lock as mutation. Settings/provider configuration/authentication reject stale writes. Persist event deduplication and outbound transaction IDs. Never rerun interrupted model executions automatically. Retry completed delivery with the original transaction ID after revalidating routing. One process lock protects each data directory.

`ScheduleStore` adds tables without rewriting existing columns. Scope all schedule creation, viewing, cancellation, claims, and delivery to the captured Agent ID, homeserver, Agent Matrix ID, owner Matrix ID, and room ID. Create requests are idempotent by source event and tool call ID; reject conflicting reuse. Accept explicit-owner one-time reminders 1 second to 365 days ahead, or daily briefings at an IANA-zone `HH:mm`; default `FAMILY_TIME_ZONE` to `Asia/Singapore`. Confirm the exact saved local time and ID only after tool success. Cap active schedules at 20 per Agent, including `needs_attention`; do not add arbitrary cron or a general workflow engine. Identity reset/deletion cancels affected jobs; never redirect old jobs or queued messages to a replacement identity. Stop pauses scheduling and Start resumes due work, marking late reminders and skipping missed daily bursts.

Claim due work with durable leases and stable occurrence transaction IDs. Complete a reminder and add its outbox message in one SQLite transaction. Return a reminder to pending only when the current lease is known not to have committed; reminder recovery can safely retry without model inference. An interrupted or uncertain briefing becomes `needs_attention` and never automatically reruns inference. Keep reminder delivery separate from model-turn serialization so long replies and model authentication failures do not block it while Matrix remains connected. Briefings serialize with Agent model turns, require the active Codex Native Login search capability, and deliver only with actual successful native search results recorded by the adapter. Missing search evidence or search failure pauses the subscription; never deliver unverified current facts. Disable schedule mutations in briefing invocations. Recheck owner-only room membership and captured identity before inference and delivery.

Show Matrix typing while processing and a bounded progress notice for slow replies. An owner cancellation in the active room aborts the current reply and tool work without cancelling previously saved schedules. Report actionable failures in the verified owner room. Preserve unrelated runtime errors when a saved reminder or an outbox message delivers successfully; only explicit runtime recovery or a successful fresh runtime operation clears them.

## Build, tests, deployment

Requirements: Node.js >=24, npm, Rust >=1.96, a C/C++ compiler and pkg-config. Run `npm ci`, `npm run check`, `npm test`, `npm run build`, and `cargo test --manifest-path gateway/Cargo.toml`. Build the Gateway with `cargo build --locked --release --bins --manifest-path gateway/Cargo.toml`; run `npm start`. `HOST` defaults to loopback, `PORT` to 18090; `GATEWAY_BIN` overrides the child executable. `/api/health` reports core readiness and Agent status.

Install Python 3 with `venv` and Poppler for local document extraction, plus the pinned packages in `deploy/python-requirements.txt` for PDF export and plotting. Create a service-owned virtual environment and set `FAMILY_PYTHON_BIN` to its Python interpreter; the generic default is `python3`. `FAMILY_TIME_ZONE` defaults to `Asia/Singapore` and must be a valid IANA timezone. Keep Python dependencies pinned and outside private application data. Use the same interpreter for PDF/chart verification. No additional service, queue broker, external search account, or API key is required for these local tools and persisted reminders; daily briefing search still depends on the explicitly selected native account's entitlement.

Codex is optional: install its CLI on the service host and set `CODEX_BIN` if needed. Protocol definitions in `server/generated/codex/` are generated from codex-cli 0.166.0; regenerate with `npm run codex:generate` when upgrading and verify safety overrides against that version. Tests use fake stdio peers and isolated native startup checks; real inference requires explicitly configured credentials and eligible account access.

Run `CODEX_BIN=/path/to/codex npm test` to include the optional native search regression. It uses a local fake Responses/search server and dummy credentials to verify the actual binary's tool-host execution, live-mode payload, and disabled local execution tools. This verifies transport and configuration; remote search authorization requires a separate live check.

The existing deployment is the `webtop-desktop` container. Its `/config/work/pith-post` is the existing repository (host bind mount `/srv/webtop/config/work/pith-post`). Run as `abc` (UID 1000), using the existing Node binary. `deploy/family-agents.run` is installed root-owned at `/srv/webtop/custom-services/family-agents`; s6 supervises it. Its Python interpreter defaults to `/config/.local/opt/family-agents-python/bin/python3`; create that virtual environment for the service user and install `deploy/python-requirements.txt` before enabling PDF/charts. Preserve the environment across restarts and pass `FAMILY_PYTHON_BIN`/`FAMILY_TIME_ZONE` through the launcher. Never restart or change the external Tuwunel homeserver. Stop Family Agents before builds that replace running executables; verify `/api/health`, both process identities, private-tailnet accessibility, and a real encrypted DM after restart. See README for the current restart commands.

## Non-goals

No replacement homeserver, Matrix chat UI, administrator/login/RBAC, configurable workspaces, per-Agent models or thinking levels, session/history/reset controls, custom memory/RAG, custom compaction, E2EE dashboard, general orchestration platform, migration/compatibility layers, or additional infrastructure. Do not reintroduce the removed Go/PocketBase/Pith/mautrix architecture.
