# Family Agents V2

Family Agents is a private LAN control panel for family-owned Matrix AI accounts. People use their existing Matrix clients to chat. The web UI has no login, administrator, roles, or chat interface. Write all source, comments, documentation, UI labels, and commits in English. Never commit private data or credentials.

## Architecture and boundaries

Exactly one Node.js/TypeScript process serves Hono and the React UI, owns SQLite metadata, supervises one Rust child, and selects one global Agent Runtime. `AgentRuntime` in `server/runtime.ts` exposes only application behavior. `PiRuntime` wraps the official embedded Pi SDK; `CodexRuntime` supervises one shared `codex app-server` over stdio with an independent persistent thread for each Agent. `RuntimeManager` holds these two adapters; do not add a plugin framework. The Rust child uses the official matrix-rust-sdk for all Agent accounts, authentication, sync, E2EE, profiles, and media. IPC is versioned JSONL on stdin/stdout; logs belong on stderr. Keep runtime SDK/protocol types inside adapters and all runtime logic out of Rust.

Each Person has a unique full Matrix ID. Each Agent belongs to one Person and has a dedicated Matrix account. Accept only decrypted messages from that owner, in an encrypted invite-only one-to-one room recorded in Matrix direct-message account data. Discover already-joined owner DMs as well as new direct invitations: after checking the authoritative pair, invite-only rules, encryption, and direct membership evidence, repair a missing Agent-side `m.direct` entry. Never require a newly created test room. Check authoritative active membership, including invitations, before execution and every send. Ignore self/outsider/group messages. Never trust frontend state for routing.

Global settings contain the homeserver, default provider/model, and thinking level. Agents contain only Matrix ID/password, display name, avatar, and instructions. Pi owns native provider/auth configuration, its catalog, capability-derived thinking levels, persistent sessions, and automatic compaction. Use built-in providers for official services; do not create duplicate application-branded provider aliases. Provider authentication has one Configure Provider action for native API-key setup, plus Sign In only where account authorization is supported. Keep the complete native JSON editor inside a collapsed Advanced Provider Configuration section. Routine connections must not require raw JSON editing. Keep all native schema properties through JSON edits and redact secrets in every response/error, while leaving ordinary token-limit metadata readable. The Default Model selector lists only SDK-available models from configured providers. Preserve an unavailable saved selection as an explanatory message rather than selecting a replacement, and prompt for provider setup when the list is empty. Use Pi's capability helpers, including custom thinking maps and Max support. Apply global model/thinking changes between turns.

Pi exposes no shell, filesystem, network, MCP, or automatically discovered extension tools. Both runtimes receive locally extracted text from supported encrypted Matrix documents; fixed parsers receive only attachment bytes on stdin, never model commands or file paths. Validate format and 8 MiB size before durable admission, bound parsing and text, preserve the owner caption, and revalidate room membership after parsing. Codex uses an isolated private home, disabled execution/extension discovery, and native live web search where the model/account permits it. Use the named `family_agent` permission profile with native filesystem access denied and command network disabled on process defaults, thread start/resume/fork, and every turn; do not override it with legacy sandbox fields. Reject unsupported approval requests; never automatically grant execution or file permissions. The fixed `send_image` tool can only return an image attached to the current message. Native image generation may use text or images already in the same conversation; local image paths must be denied before upload. Enable it only outside SIWC and let native model/account gates apply. Accept generated bytes or the exact private native thread/item artifact, validate image type/size and links, correlate the active turn, deduplicate completion events, and cap output to four images/8 MiB total. Instructions append to Pi's essential prompt or use Codex's persistent developer instructions, isolated by Agent.

Responses Lite models invoke native tools through the isolated Code Mode host. Keep `features.code_mode_host=true` and the matching `codex-code-mode-host` companion installed, while shell/browser/computer-use tools remain disabled and `features.code_mode=false`. The SIWC provider must declare `supports_standalone_web_search=true`; `web_search=live` alone does not expose that provider's search tool. SIWC search uses `/v1/alpha/search`, which has separate authorization requirements from `/v1/responses`; managed native ChatGPT uses its own built-in Codex backend and authentication. A successful SIWC login or model turn does not prove search entitlement. Report a search authorization failure accurately; never enable unrestricted execution or change authentication routes to hide it. Matrix replies are plain text: use source names with bare HTTPS URLs instead of Markdown links.

Runtime selection defaults to Pi for existing installations. Settings retain independent defaults for Pi and Codex; provider configuration stays Pi-native. Codex retains three explicitly selected connections: current open-source Sign in with ChatGPT, Codex-managed native ChatGPT login, and native API-key login. Keep their credentials independent; signing out clears only the selected connection. Existing SIWC remains selected on upgrade. `ChatGptAuth` owns protected registrations, a stable host ID, PKCE/state/nonce, verified identity tokens, manual callback-URL input, and serialized rotating-token refresh. It is separate from Pi credentials and the desktop Codex account. Never automatically fall back between connections after an authorization or search failure. Native OAuth and rotating-token refresh stay owned by Codex; snapshot its latest opaque credential file only after the child stops, and restore the selected cache before starting it. Pending native login must prevent new executions from crossing its authentication change. Codex model discovery and reasoning metadata still use native `model/list`. Pass SIWC access tokens only in the child environment to the documented Responses provider at `https://api.openai.com/v1`; never in process arguments, logs, or HTTP responses. Refreshing the token may restart the shared App Server only after existing execution leases drain; new turns wait and saved threads resume without replay. Internal cancellation must not wait for its own execution lease. Keep the public SIWC provider definition registered in native/API-key mode so stored SIWC history can resolve its original provider; supply its token only when SIWC is selected. A provider mismatch after an explicit connection switch requires native `thread/fork` with the saved history; retain the source, persist the new mapping, and never replay an old turn. Do not treat missing history or arbitrary resume errors as a provider mismatch. Authentication completion restores desired Agents and starts only missing Matrix clients. Gateway Running status proves transport connectivity; it must not clear a runtime/session/delivery error. Clear those errors only after explicit recovery or a successful fresh operation.

Validate target readiness before switching. Pause new turns while durably admitting Matrix events, drain active Agent operations (cancel after a bounded wait), prepare target sessions, deactivate the old runtime, then persist selection. Restore the previous runtime on failure. Never restart Matrix devices just to switch runtimes, convert session formats, replay an uncertain execution, or delete conversation data during switching. Codex process exits fail active turns and reconnect only for fresh operations. Use separate locks for settings writes and Agent queues so draining Agent operations cannot wait on its own settings write.

## Storage and consistency

`DATA_DIR` defaults to `data/`, with mode 0700 and files 0600:

- `application.sqlite`: People, Agent metadata, optimistic versions, global settings, durable inbox/outbox. Matrix passwords are in a separate encrypted credentials table; `credentials.key` must be backed up with it.
- `pi/models.json`, `pi/auth.json`: Pi-native configuration and authentication, accessible only to the service account.
- `agents/<id>/sessions/`: Pi-native persistent conversation files; restore automatically. No session state is duplicated in SQLite.
- `codex/home/`: private Codex-native credentials and conversation storage; `codex/agents/<id>/` contains isolated internal working directories and atomic thread mappings. Keep these independent from Pi sessions and the desktop user's Codex account.
- `codex/auth-connections/`: private explicit-method selection and separate opaque native ChatGPT/API-key credential snapshots. Preserve rotated native credentials during switching and rollback.
- `codex/siwc/`: private Sign in with ChatGPT host identity, separately retained account/client registrations, and renewable credentials. Write credentials atomically with 0600 permissions. Verify issuer/signature/audience/expiry/nonce and direct-use scopes before activating an account; preserve the previous connection if authorization fails. Sign-out clears tokens, retains account/client mappings, and attempts remote renewable-session revocation.
- `matrix/<id>/`: SDK SQLite state/crypto stores, original device session, sync cursor, durable pending-event spool, and private native `identity-secrets.json`. Match all recovered signing public keys against the server before importing, sign the current device with the existing identity, and preserve signing secrets separately across bounded crypto-DB recovery. Never replace an unknown account identity. Acknowledge spool events only after SQLite admission commits. Restore normal devices; classified corruption recovery is bounded and archives the previous state.

Serialize messages and lifecycle changes per Agent; different Agents run concurrently. Check record versions under the same lock as mutation. Settings/provider configuration/authentication reject stale writes. Persist event deduplication and outbound transaction IDs. Never rerun interrupted model executions automatically. Retry completed delivery with the original transaction ID after revalidating routing. One process lock protects each data directory.

## Build, tests, deployment

Requirements: Node.js >=24, npm, Rust >=1.96, a C/C++ compiler and pkg-config. Run `npm ci`, `npm run check`, `npm test`, `npm run build`, and `cargo test --manifest-path gateway/Cargo.toml`. Build the Gateway with `cargo build --locked --release --bins --manifest-path gateway/Cargo.toml`; run `npm start`. `HOST` defaults to loopback, `PORT` to 18090; `GATEWAY_BIN` overrides the child executable. `/api/health` reports core readiness and Agent status.

Codex is optional: install its CLI on the service host and set `CODEX_BIN` if needed. Protocol definitions in `server/generated/codex/` are generated from codex-cli 0.166.0; regenerate with `npm run codex:generate` when upgrading and verify safety overrides against that version. Tests use fake stdio peers and isolated native startup checks; real inference requires explicitly configured credentials and eligible account access.

Run `CODEX_BIN=/path/to/codex npm test` to include the optional native search regression. It uses a local fake Responses/search server and dummy credentials to verify the actual binary's tool-host execution, live-mode payload, and disabled local execution tools. This verifies transport and configuration; remote search authorization requires a separate live check.

The existing deployment is the `webtop-desktop` container. Its `/config/work/pith-post` is the existing repository (host bind mount `/srv/webtop/config/work/pith-post`). Run as `abc` (UID 1000), using the existing Node binary. `deploy/family-agents.run` is installed root-owned at `/srv/webtop/custom-services/family-agents`; s6 supervises it. Never restart or change the external Tuwunel homeserver. Stop Family Agents before builds that replace running executables; verify `/api/health`, both process identities, private-tailnet accessibility, and a real encrypted DM after restart. See README for the current restart commands.

## Non-goals

No replacement homeserver, Matrix chat UI, administrator/login/RBAC, configurable workspaces, per-Agent models or thinking levels, session/history/reset controls, custom memory/RAG, custom compaction, E2EE dashboard, general orchestration platform, migration/compatibility layers, or additional infrastructure. Do not reintroduce the removed Go/PocketBase/Pith/mautrix architecture.
